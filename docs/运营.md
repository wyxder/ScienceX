## 一、项目现状分析与目标定位

### 1.1 产品现状盘点（As-Is）

| 维度 | 当前状态 | 运营含义 |
| :--- | :--- | :--- |
| **产品完成度** | 13 大功能模块全部有页面与接口闭环：AI 对话工作台、选题灵感、文献阅读、实验设计、数据分析、论文写作、投稿助手、组会汇报（DreamPaper）、专家评审团、项目课题组、个人中心、认证、官网 Landing | 可对外承诺"全链路科研工作台"，而非单点工具；演示脚本可覆盖研究生完整科研周期 |
| **AI 能力** | 已落地真实模型网关（DeepSeek V4.1 Flash，OpenAI 兼容协议 + 用户私有模型接入）、灵犀引擎 8 类 Agent 编排（ReAct / Plan-Execute / CodeAct / MCP / Text2SQL / Structured 等）、三层记忆、SSE 7 类事件流式推送；无密钥时确定性模板回退 | "Agent 可视化 + 多智能体评审团"是最强差异化叙事，运营素材应围绕它展开 |
| **可信度** | 跨源 DOI/arXiv 去重、引用页码溯源、"无证据不伪造"强制拒答评测（12 条学术质量评测含 4 条禁止编造强制项） | 学术诚信是科研用户对 AI 工具最大的顾虑，可直接转化为品牌信任资产 |
| **工程质量** | GitHub Actions CI 全量回归（后端测试 + 覆盖率门禁 + eval 模板质量回归 + 前端 typecheck/lint/build）；55/55 自动化用例通过；21 项人工验收通过 | 有公开可复现的质量证据链，冷启动期可用作"极客信誉"背书 |
| **安全与多租户** | HMAC-SHA256 无状态令牌、多租户资源隔离、SSRF 拦截、批量赋值白名单、限流按 userId 分桶（已由 fx.md 的 S0/S1 阶段修复落地） | 可承接真实注册用户，具备商用底座 |
| **部署形态** | 前端 + 后端均部署 Vercel（Serverless），本地 JSON 文件持久化容错模式；SSE 长连接在 Serverless 上存在被平台中断的风险（fx.md B13 已知项） | 运营放量前需解决承载与流式稳定性，否则拉新流量会被体验事故吞噬 |
| **商业化** | 官网有订阅定价卡片（个人/团队分档）与演示账号；尚无任何真实支付通道、免费额度策略、订阅开通闭环 | 转化路径存在"最后一公里"缺口，是增长方案重点补齐对象 |
| **现有传播资产** | 官网宣传页（含动态渐变标题、人物画像区、定价卡）、系统架构图 / Agent 流程图 SVG、宣传演示视频（`image/ScienceX视频演示.mp4`）、参赛路演答辩材料（30 个高频评委问题库） | 冷启动素材库已有约 70%，缺的是分发节奏与内容再加工 |

### 1.2 关键短板（运营视角）

1. **无真实用户数据回流机制**：当前埋点仅覆盖 token 用量统计，缺少访问→注册→激活→留存漏斗指标，运营决策"盲飞"。
2. **激活路径长**：新用户注册后面对 13 个模块，没有新手引导（Onboarding Tour）与"Aha 时刻"设计，首会话价值获取概率低。
3. **转化闭环缺失**：订阅卡只是展示，没有支付接入（可借助支付宝 AI 付等通道）、没有免费额度→付费的升级钩子。
4. **留存抓手弱**：无邮件/站内信召回、无周报（"本周你的科研进展"）、课题组协作黏性未成体系。
5. **文档与预期管理**：fx.md 指出的"文档承诺 vs 实现"落差已基本按 As-Is 口径修正，但对外宣传仍需统一"演示原型 + 真实 AI 已接入"的话术，避免口碑反噬。

### 1.3 目标定位与增长北极星

- **产品定位一句话**：面向科研人的全链路 AI 工作台——从选题、文献、实验、写作到投稿，用 8 类智能体编排和可溯源的多智能体评审，做"敢让你写进论文里"的科研 AI。
- **差异化主张（对位竞品）**：
  - 对通用聊天 AI（ChatGPT/Kimi/豆包）：**科研流程专属编排 + 溯源引用 + 评审团**，不是聊天框，是工作台；
  - 对单点科研工具（Connected Papers、ScholarAid、NotebookLM 等）：**全周期一体化**，一个账号跑通选题到投稿；
  - 对高校自建系统：**私有模型接入 + 多租户隔离**，课题组数据不出域。
- **北极星指标**：**周活跃科研任务完成数**（WATC，Weekly Active Task Completions）——单用户完成一次"有产出物的任务"（综述大纲 / 开题报告 / 评审报告 / 图表 / PPT）计 1。它同时约束"拉新要有质量、留存要有价值、转化要有交付"，避免 DAU 虚高。

### 1.4 阶段目标（12 个月）

| 阶段 | 时间 | 目标 | 关键结果（KR） |
| :--- | :--- | :--- | :--- |
| T0 参赛收割期 | 第 1-2 月 | 把比赛流量吃干净 | 路演/展览曝光 ≥ 5 万次；官网 UV → 注册转化率 ≥ 8%；种子用户 ≥ 300 |
| T1 冷启动验证期 | 第 3-5 月 | 跑通激活-留存模型 | 注册 → 首任务完成（激活）≥ 40%；次周留存 ≥ 25%；NPS ≥ 30 |
| T2 渠道放量期 | 第 6-9 月 | 建立可复制获客渠道 | 月新增注册 ≥ 2000；K 因子 ≥ 0.4；免费 → 付费转化 ≥ 3% |
| T3 商业闭环期 | 第 10-12 月 | 验证订阅收入模型 | 付费用户 ≥ 300 或课题组（团队版）≥ 10 个；MRR ≥ ¥1.5 万；CAC/LTV ≤ 1:3 |

## 二、目标用户画像与核心增长指标

### 2.1 三层用户画像（与官网 Persona 区一致）

| 画像 | 对应官网人物 | 核心痛点 | ScienceX 价值锚点 | 决策特征 | 优先级 |
| :--- | :--- | :--- | :--- | :--- | :---: |
| **P1 研究生（硕士/博士）** | `grad_student` | 文献读不完、综述写不出、开题没头绪、组会被骂 | 选题灵感 + 文献阅读问答（溯源到页码）+ 综述/开题生成 + 组会 PPT（DreamPaper） | 自费小额订阅（¥20-50/月）或白嫖免费额度；受同学口碑影响大 | ⭐⭐⭐ 主攻 |
| **P2 青年学者 / 博后 / 讲师** | `early_scholar` | 投稿选刊难、审稿意见回复繁琐、跨方向拓展慢 | 投稿助手期刊匹配 + 专家评审团（5 角色并行审稿预演）+ 润色翻译术语库 | 付费意愿最强；关注学术诚信与数据安全 | ⭐⭐⭐ 主攻 |
| **P3 课题组 PI / 实验室** | `lab_pi` | 组内数据分散、重复劳动、新人上手慢、工具无法统一采购 | 项目与课题组空间 + 多租户隔离 + 私有模型接入（数据不出域） | 团队批量采购决策者，周期长但 LTV 高 | ⭐⭐ 第二曲线 |

> **打法结论**：P1 管"量"（传播、口碑、拉新），P2 管"钱"（订阅转化主力），P3 管"稳"（团队版高留存高 LTV）。运营资源按 5:3:2 投放。

### 2.2 核心增长指标体系（AARRR 双刃剑：既有增长，也有质量红线）

| 层级 | 指标 | 定义 | T1 目标 | T2 目标 | 责任人 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 获客 Acquisition | 官网 UV / 各渠道 CTR / 注册数 | 分渠道 UTM 归因 | 月注册 500 | 月注册 2000 | 内容运营 |
| 激活 Activation | **首任务完成率**：注册后 7 日内完成 1 个有产出物任务 | 事件 `task_done` | ≥ 40% | ≥ 50% | 产品 |
| 激活 | Time-to-Value（首次产出物耗时） | 注册 → 首个 `task_done` 中位数 | ≤ 15 分钟 | ≤ 10 分钟 | 产品 |
| 留存 Retention | 次周 / 次月留存 | 有登录且有任务 | W2 ≥ 25% | W2 ≥ 30%，M1 ≥ 20% | 产品+运营 |
| 收入 Revenue | 免费→付费转化率 / MRR / ARPU | 订阅生效口径 | 转化 ≥ 1.5% | 转化 ≥ 3%，MRR 破万 | 商业化 |
| 推荐 Referral | K 因子 / 邀请注册占比 / GitHub Star | 邀请链路闭环统计 | K ≥ 0.2 | K ≥ 0.4，Star ≥ 1k | 社区运营 |
| **质量红线** | AI 幻觉投诉率 | 用户举报"编造引用/数据"的会话占比 | ≤ 0.5% | ≤ 0.3% | 质量负责人 |
| **质量红线** | SSE 流式中断率 | 长回答断流/丢字事件占比 | ≤ 2% | ≤ 1% | 后端 |
| **质量红线** | 单用户月模型成本 | usage 真实计量聚合 | 监控 | ≤ 订阅毛利 50% | 商业化 |

> 质量红线与增长指标同权重考核：科研产品一次"AI 编造文献"的公开翻车足以抵消一个月内容投放，**可信度就是增长本身**。

## 三、分阶段运营策略与执行计划

### 阶段 T0（第 1-2 月）：参赛势能收割

**策略**：比赛是免费的信任背书 + 精准流量，把所有参赛物料二次加工成公开传播资产。

| 周次 | 动作 | 交付物 |
| :--- | :--- | :--- |
| W1-2 | ① 官网话术定稿：统一"真实 AI 已接入 + 溯源可信"As-Is 口径（依据 fx.md 落差清单逐条核对，杜绝过度承诺）；② 部署体验环境压测：模拟 100 并发 SSE，验证 Vercel 限流分桶与断线续传（B9/Last-Event-ID），修复 B13 风险或发布"长任务用异步任务流"的引导文案 | 话术白名单文档；压测报告 |
| W2-4 | ③ 路演视频剪辑：将 `ScienceX视频演示.mp4` 切成 3 支 60s 竖版短视频（选题-文献-评审团各一支）投放视频号/B站/抖音；④ 架构图/Agent 流程图 SVG 做成技术长文《我们如何用 8 类 Agent 编排做科研工作台》发知乎/掘金 | 3 支短视频 + 2 篇技术长文 |
| W4-8 | ⑤ 获奖/参赛结果公示页上线官网；⑥ 建立种子用户群（微信/QQ 群，目标 300 人）：参赛结识的同学、评委、观众，入群送"内测额度包"；⑦ 上线最小埋点（注册/激活/任务完成/分享 4 类事件 + UTM 归因） | 种子群 300 人；数据看板 v1 |

**关键假设验证**：参赛流量 → 注册的转化率是否 ≥ 8%；若低于 5%，优先修注册流程（当前注册密码下限 6 位、中文字段校验提示已优化）与官网 CTA，再谈放量。

### 阶段 T1（第 3-5 月）：冷启动激活与留存验证

**策略**：不急于投放，先把"漏水的桶"补好——围绕北极星 WATC 重塑激活路径。

1. **Aha 时刻工程**：定义新用户首会话推荐路径——注册后直接进入"3 分钟体验评审团"或"上传一篇 PDF 问它三个问题"两个最短价值路径；上线 Onboarding（3 步引导 + 预置示例课题），把 Time-to-Value 压到 15 分钟内。
2. **免费额度策略**：新号送 N 次完整任务额度（而非无限闲聊），额度耗尽页展示"本次为你生成的产出物清单"（综述大纲/图表/评审报告），用"差点就有"制造升级动机；日任务上限同时兜住 Serverless 成本与 fx.md B7 限流红线。
3. **留存钩子**：①科研周报（本周完成任务、新增文献、写作字数，邮件+站内）；②会话/项目续写提醒（7 日未回访的未完成任务推送"你的开题报告还差两步"）；③课题组异步协作（共享知识库、成员动态）作为团队留存抓手提前灰度。
4. **口碑种子**：种子群内做"体验官计划"——周度任务打卡（用选题/文献/评审任一功能交作业），优质反馈署名进 Release Notes；产出 20 条可公开引用的用户证言（分 P1/P2 两类人群收集）。
5. **学术诚信营销点**：公开 12 条学术评测集运行方法与结果（`eval/run.js`），发布《我们如何测试 AI 不胡说八道》，抢占"可信科研 AI"心智，同步冲击"AI 编造参考文献"这一全网高频痛点话题。

**退出标准**：W2 留存 ≥ 25% 且激活 ≥ 40% 连续 4 周成立 → 进入 T2；未达标则延长 T1，禁止烧钱投放。

### 阶段 T2（第 6-9 月）：渠道放量与推荐循环

**策略**：T1 验证过的信息流 + 内容矩阵复制到全渠道，同时启动增长飞轮三件套。

1. **内容矩阵常态化**（详见第五章）：SEO 长文 + 社媒短视频双轮，月产 8-12 篇/条，主打"场景词"（文献综述生成、AI 审稿、开题报告模板）而非品牌词。
2. **推荐飞轮**：①邀请机制——邀请 1 人双方各得任务额度，上限防刷；②产出物裂变——综述/评审报告导出页带"由 ScienceX 生成"水印 + 体验链接（去掉水印为付费权益）；③GitHub 开源部分模块（如前端图表引擎、评测集），README 导流主站。
3. **渠道合作**：高校图书馆/研究生会联合"AI 科研工具培训"讲座（线上为主，成本可控）；与科研博主（知乎/B站学术区）做 3-5 场"用 ScienceX 现场复现一篇论文思路"直播；KOL 专属注册链接分佣或送额度。
4. **转化优化**：接入真实支付（支付宝 AI 付/网页支付通道），订阅管理页闭环（下单→开通→额度实时生效→续费提醒→发票）；A/B 测试定价卡（月付/年付锚定、品红渐变版 vs 简约版文案）。
5. **团队版破冰**：从个人付费用户中筛 20 个"带学生账号"的 PI，送 30 天团队版试用，收集组织协作需求，打磨第一版团队定价。

### 阶段 T3（第 10-12 月）：商业化与生态深化

1. **收入结构**：个人订阅（主力）+ 团队版（3-10 个标杆课题组）+ 按需加油包（额度包），三档互补；月度 LTV/CAC 复盘，砍掉 CAC/LTV > 1:1 的渠道。
2. **供给生态**：Skill 技能包与 MCP 工具目录开放"用户自定义"，优质技能作者送额度——把 P2 用户变成内容生产者；上线"科研 Prompt/工作流模板"分享页（每个模板 = 一个 SEO 落地页 = 一个注册入口）。
3. **品牌升维**：发布年度《AI 科研诚信白皮书》（基于评测集方法论 + 匿名使用数据洞察），从工具品牌升级为话题品牌。
4. **续费保卫**：年付到期前 30/7/1 天三级触达；流失用户问卷回收与"召回礼包"（老用户回归送双倍额度）。

## 六、数据监测与效果评估机制

### 6.1 数据基建（三步走，避免过度建设）

1. **第 1 个月（能看漏斗）**：前端埋点 SDK（自研轻量 fetch 上报或 Vercel Analytics）+ 后端 4 类核心事件（`signup` / `activate`(task_done) / `quota_exhausted` / `share_click`），全部带 UTM 与 `request_id`（后端已有 X-Request-Id 全链路基础设施，直接复用）。
2. **第 2-3 个月（能看留存与成本）**：cohort 留存曲线（按渠道/周分桶）、单用户模型成本（usage 真实计量已有，加运营维度聚合）、SSE 中断率与任务失败率（质量红线看板）。
3. **第 4 个月起（能算钱）**：LTV/CAC 模型、渠道归因（首触 + 末触双口径）、A/B 实验平台（先用最简 hash 分流，不引重型框架）。

### 6.2 常规评估节奏

| 机制 | 频率 | 参与人 | 输出 |
| :--- | :--- | :--- | :--- |
| 指标复盘会 | 周 | 运营 + 产品 | 漏斗异动清单、渠道量级/成本表 |
| 质量红线巡检 | 周 | 后端 + 质量 | 幻觉投诉、断流率、限流误伤报告（CI 已有 55 条回归 + eval `--check` 门禁，运营事件并入同一看板） |
| 渠道 ROI 评审 | 月 | 全员 | 渠道预算再分配，连续 2 月 CAC 超线渠道暂停 |
| 用户访谈 | 月 4-6 人 | 产品 + 运营 | P1/P2/P3 各覆盖；流失用户优先 |
| 阶段闸门评审 | 双月 | 负责人 | T0→T1→T2→T3 晋级/延期决策（依据 1.4 KR） |

### 6.3 实验文化

- 每个渠道落地页、每次定价卡改版、每封召回邮件均以 A/B 或前后对照评估，**预设样本量与观察期才上线**，杜绝"感觉有效"。
- 内容侧以"完播率/收藏率 → 带码注册"两级漏斗考核，低于基线的选题进淘汰池。
