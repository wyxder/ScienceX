# ScienceX 复现指南（评委 / 开发者）

> **目标**：从克隆仓库到亲眼看到可交互界面，**5 分钟内完成**；并用一条命令验证核心结论（测试、类型、构建）。
> **适用对象**：评委、答辩现场、二次开发。
> **对应交付规范**：区域赛「交付规范性」——文档清晰、可按文档复现。

---

## 一、前置条件

| 依赖 | 版本要求 | 必需性 | 说明 |
| :--- | :--- | :---: | :--- |
| Node.js | ≥ 18（推荐 20 LTS / 22） | ✅ | 前后端运行时 |
| npm | ≥ 9 | ✅ | 依赖安装 |
| Python + PyMuPDF | 3.8+ | ⭕ 可选 | PDF 原生文本层提取；未安装时自动降级为内置解析 |
| 浏览器 | Chrome / Edge 近两年版本 | ✅ | 支持 SSE 与 ES2020 |

> Windows 用户使用 PowerShell 或 Git Bash 均可；下文命令以任意终端为准。

## 二、5 分钟启动

```bash
# 1. 安装依赖（首次约 1–2 分钟）
cd backend && npm install
cd ../frontend && npm install

# 2. 配置环境变量（可跳过，跳过则走演示模板）
cd ../backend
cp .env.example .env      # Windows PowerShell: Copy-Item .env.example .env
# 按需填写 DEEPSEEK_API_KEY（不填也能完整走通界面流程）

# 3. 启动后端（终端 A）
npm run dev               # 默认 8787；端口占用会自动 +1 并写入 backend/.port

# 4. 启动前端（终端 B）
cd ../frontend
npm run dev               # 默认 5173，自动读取 backend/.port 配置代理
```

访问 **http://localhost:5173**，演示账号：

```text
邮箱：demo@sciencex.cn
密码：123456
```

## 四、关键环境变量（最小集）

| 变量 | 作用 | 不配置的后果 |
| :--- | :--- | :--- |
| `DEEPSEEK_BASE_URL` / `DEEPSEEK_API_KEY` / `DEEPSEEK_MODEL` | 默认模型网关 | 回退演示模板，界面可走通但非真实生成 |
| `SCIENCEX_MASTER_KEY` | HMAC 签名主密钥；生产需 ≥32 字符且多实例一致 | 开发环境回退演示密钥并告警；生产受保护接口拒绝服务 |
| `CORS_ORIGINS` | 跨域白名单 | 默认仅允许 `localhost:5173` |
| `PORT` | 后端端口 | 默认 8787，冲突自动递增 |
| `ALIPAY_*` | 支付宝网页支付 | 支付不可用，其余功能不受影响 |
| `HARNESS_EVAL_ENABLED` | 质量中心开关 | 默认 `true` |

完整 30 余项配置见 `backend/.env.example`（含生图、Embedding、限流、Harness、模型价格等）。

## 五、常见问题

| 现象 | 原因 | 处理 |
| :--- | :--- | :--- |
| 前端 502 / 接口 404 | 后端未启动或端口不一致 | 先启动 backend，确认 `backend/.port` 内容；重启 Vite |
| 端口被占用 | 8787 或 5173 已被占用 | 后端会自动递增；前端 Vite 会提示换端口，按提示访问 |
| 页面能开但回答是模板 | 未配置模型密钥 | 在 `backend/.env` 填 `DEEPSEEK_API_KEY` 后重启 |
| PDF 解析慢/失败 | 未装 PyMuPDF 或文档过大 | 可忽略（自动降级）；大文档改用分段精读 |
| `SCIENCEX_MASTER_KEY` 告警 | 未配置生产密钥 | 开发可继续；生产必须配置统一密钥 |
| 支付按钮无响应 | 未配置 `ALIPAY_*` | 属预期，支付能力需商户配置 |

## 七、生产部署（两种路径）

**路径 A · Vercel（仓库已配置）**

- `vercel.json` 声明 frontend 与 backend 双服务，`/api/*` 重写至后端；
- 多实例必须配置统一的 `SCIENCEX_MASTER_KEY`（HMAC 无状态令牌可离线验签）。

**路径 B · Docker + Nginx**

```bash
docker build -t sciencex-backend ./backend
docker run -d -p 8787:8787 --env-file backend/.env -v sciencex-data:/app/.data sciencex-backend
cd frontend && npm run build    # 产物 dist/ 交 Nginx
```

Nginx 关键配置（SSE）：

```nginx
location /api/ {
    proxy_pass http://127.0.0.1:8787;
    proxy_http_version 1.1;
    proxy_set_header Connection '';
    proxy_buffering off;
    proxy_read_timeout 300s;
}
```

## 八、复现失败时的排查顺序

1. `node -v` 是否 ≥18；
2. 两端依赖是否装齐（`backend/node_modules`、`frontend/node_modules`）；
3. 后端是否真正监听（`backend/.port`、终端日志 `server listening`）；
4. CORS 白名单是否包含当前前端地址；
5. 是否误把 `.env` 提交/覆盖（应只改 `.env.example` 的副本）；
6. 仍失败时执行 `node scripts/verify.mjs`，把输出与 `X-Request-Id` 一并反馈。
