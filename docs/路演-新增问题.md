## 一、产品问题

### Q31：产品的差异优势点是哪些？和豆包大模型有哪些区别？
**参考回复**：先定位关系：豆包是通用大模型与通用助手，我们是垂直科研场景的工作台，二者是"引擎 vs 工厂"的关系，不是正面竞争。三个差异：① 豆包交付"一次对话"，我们交付"一个课题"——选题 → 文献 → 复现 → 实验 → 分析 → 写作 → 投稿 → 协作全流程，上下文跨阶段流转并沉淀为资产，不需要在对话框之间复制粘贴；② 我们有通用对话没有的领域机制——五角色评审团盲审、消融矩阵、CAJ 解析、CCF 期刊匹配、页码级引用溯源；③ 模型中立：豆包这类 OpenAI 兼容模型可以通过我们的模型网关接入成为底层引擎之一，我们的价值在工作流与数据资产，不绑定任何单一模型。一句话：**豆包回答问题，ScienceX 完成课题。**

### Q32：「调研↓60%」「精读↓50%」这些数字哪来的？
**参考回复**：诚实回答——这是产品设计阶段基于任务分解的**目标估算值**，不是大规模用户实测结论。估算逻辑是把传统流程拆解计时：选题调研传统要跨多个数据库检索、手动去重筛选、逐篇初读，多源聚合 + DOI 去重 + 可行性评估把机械环节压缩，得到约 60% 的目标降幅；单篇精读的翻译、七段式总结、思维导图替代了大部分逐句阅读，得到约 50% 的目标降幅。上线后我们会用真实埋点（全流程完成率、单篇精读耗时）替换估算值，所有对外材料都会区分"目标值"与"实测值"。（主动亮出估算口径，比被追问后承认更可信。）

### Q33：产品面向目标用户是谁？哪些场景？
**参考回复**：用户分三层（市场规模口径见主手册 Q11）：① 硕博研究生——核心付费人群，论文是硬 KPI；② 课题组/实验室——导师 PI 带学生团队，天然团队版客户；③ 高校与科研院所——私有化部署。场景对应科研四段：**选题开题**（多源检索 + 可行性评估 + 一键开题报告）、**文献研读**（双语精读、七段总结、引用图谱、RAG 问答）、**实验与复现**（实验设计、科研配图、五阶段复现流水线）、**写作投稿**（润色降重、评审团预审、组会 PPT 一键生成）。移动端覆盖"轻消费"场景——看进度、审报告、读推送。

### Q34：商业模式如何考虑的？未来计划发展？
**参考回复**：商业模式是"四档订阅 + 私有化"：免费探索版获客 → 19.9 元/月学生价渗透（把决策门槛打穿，靠课题组内口碑扩散）→ 199 元/月课题组版（5-15 人共享，B 端入口）→ 机构私有化定制（数据不出校门）。成本端靠模型路由 + BYOK + 缓存保障毛利。发展计划三步：① 真实执行器——CodeAct 沙箱与复现流水线 Docker/Wasm 化；② RAG 生产化——pgvector + Rerank；③ 私有化一键交付 + 国产模型（Qwen/GLM）适配，先拿高校信息中心订单；长期押注自主科研 Agent——给定假设自动检索、设计实验、验证、出报告。

## 二、技术问题

### Q35：多智能体 5 个专家评审团分工怎样？技术上如何编排？
**参考回复**：分工对齐真实审稿链路：理论审稿人（推导、公式、假设边界）、方法审稿人（架构、创新性、复杂度）、实验审稿人（数据集、评测协议、消融、统计显著性）、写作审稿人（结构、图表、符号一致性）、伦理审稿人（数据授权、隐私、偏见、学术诚信），另设主席（Senior Area Chair）合议。编排实现：每个角色是带独立 system prompt 的 Agent，提示词中"严禁越界评价其他维度"；五角色**并行调用**模型（温度 0.3），约定 JSON 结构化输出（score / verdict / comments），配宽松 JSON 提取 + 失败重试一次 + 逐角色示例回退的容错链；主席 Agent 汇总五份意见产出 Meta-Review——最终决策、总分、分歧点、P0/P1/P2 优先级修改清单，主席失败时按五人均分确定性回退。本质是**用角色对抗压低单一模型的确认偏误**。

### Q36：论文 RAG 检索准确性如何保障？如何减少模型幻觉？
**参考回复**：准确性四层保障：① 结构化切片——按解析出的章节切 1000 字窗口，每片携带章节标题与段落级页码（含页码校验标记），不是无脑全文切碎；② 向量 + 词法双路——Embedding 余弦检索为主，Embedding 服务不可用时自动降级词法检索，熔断 + 重试保证可用性，检索模式如实返回前端展示；③ 可选 Rerank——开关开启后由模型对候选片段重排，重排结果做合法性校验（ID 集合一致才采纳）；④ 引用溯源——每个回答通过 reference 事件附带文档 ID、页码、章节、原文片段与得分，前端可点击回原文。防幻觉上：提示词约束"只基于检索片段作答"；检索为空时直接告知无可用片段，而不是让模型编造；降级 / 回退状态在 UI 明确标识。我们不承诺消灭幻觉，承诺**每一句输出可核查**。

### Q37：论文数据隐私如何确保不泄露？
**参考回复**：四层：① 部署层——支持私有化部署与 BYOK，敏感数据可完全不出用户自己的模型边界，用户数据不用于模型训练（写入服务条款）；② 隔离层——多租户资源可见性统一规则（owner/admin/member），个人资产 owner 严格匹配，课题组按角色授权；删除文档时同步清理知识库残留切片，避免已删文献继续被检索命中；③ 传输与审计层——HMAC-SHA256 签名令牌鉴权，X-Request-Id 全链路追踪，日志不落敏感字段；④ 模型层——用户自带密钥仅本人可见，托管密钥隔离存储。在科研场景，隐私不是合规成本，是核心卖点。

### Q38：论文解析预览如何实现的？
**参考回复**：解析引擎零第三方 Node 依赖，覆盖 PDF / Word(.docx) / Markdown / CAJ 四格式：PDF 优先委托 PyMuPDF 提取文本层（环境不具备时降级 pdfminer / pypdf，仍失败则降级占位结构并在元数据中明确标识）；Word 直接解 OOXML——纯 Node 解 zip、逐段落节点提取；CAJ 通过版本头（CAJ-C / TEBX / HN）识别，内部保留 PDF 文本流的做内联解析，否则启发式提取。所有格式统一产出 sections / figures / meta 结构化 JSON：标题、作者、分节段落、段落级页码映射。前端阅读器按这套结构渲染原文预览、双语精翻与思维导图，RAG 切片也复用同一结构——**一份解析产物支撑阅读、问答、检索三个场景**。CAJ 支持是针对国内知网场景的差异化细节。

### Q39：论文复现如何实现的？
**参考回复**：五阶段流水线：**代码解析 → 环境构建 → 数据准备 → 基线对齐 → 结果比对**。用户选择开源论文或上传自己的文档，系统解析方法与实验配置自动生成复现方案，按阶段推进并输出与原文逐指标对照的可复现性报告——偏差会做归因（随机种子波动、数据集修订版差异等），判定"复现成功 / 失败"并归档到项目资产库。诚实边界：当前为高保真演示编排，阶段日志与比对数值为建模数据；真实执行器在路线图上——Docker / Wasm 隔离沙箱真实跑代码、指标真实复算，完成后"结果比对"就是真实实验输出。
