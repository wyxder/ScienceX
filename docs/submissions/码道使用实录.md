## 五、工作方法：为什么不是"让 AI 随便写"

### 5.1 契约先行

```text
Zod schema（backend/shared/api-schemas.js）
  ├─ 运行时请求校验
  ├─ OpenAPI 文档同源生成（/api/v1/openapi.json）
  └─ 契约测试（routes.contract.test.js）进 CI
```

生成任何路由前先定契约，避免前后端字段漂移；这也是 110 个端点能保持统一响应的原因。

### 5.2 最小验证 + 全量回归

每次改动按"最小用例 → 相关套件 → 全量 74 条 → 前端 typecheck/build"逐级验证，失败先定位根因再改，不做"猜着改"。

### 5.3 规则固化

`AGENTS.md` 规定每累计 2 次代码修改自动提交并推送，提交信息必须中文语义化；禁止提交 `.env`、密钥、构建产物。规则把"记得提交"变成流程默认动作，182 次提交因此保持可读。

## 六、Prompt 设计：模板与真实样例

### 6.1 五段式模板

```text
【角色】在 ScienceX 仓库中工作的全栈工程师，遵循 AGENTS.md 与既有代码风格。
【上下文】相关文件清单 / 现有契约位置 / 不可改动范围。
【任务】要实现的行为、输入输出结构、异常分支。
【约束】不新增依赖；沿用统一响应与错误码；SSE 事件顺序不变；不编造数据。
【验收】给出可执行命令与预期结果；失败先定位根因。
```

**反面示例**（实际避免的写法）：
> "帮我优化一下支付页面。"

问题：没有现象、没有文件范围、没有验收标准，生成结果不可验证，也无法判断是否引入回归。

### 6.2 样例一：故障定位

```text
【现象】点击订阅后界面停留在"正在创建收银台"，无超时也无报错。
【上下文】frontend/src/pages/Account.tsx、frontend/src/pages/landing/LandingPricing.tsx、
         backend/src/routes/payment.js；不要改支付宝 SDK 封装。
【任务】判断阻塞在前端状态机还是后端下单；给出最小修复。
【约束】收银台窗口必须在点击同步阶段打开；接口失败要有可读提示；回跳核销必须以订单查询结果为准。
【验收】异常路径 25 秒内提示；不出现"支付成功但权益未开通"。
```

结果：提交 `f2ba253`，两个入口行为一致，回跳按订单状态核销。

### 6.3 样例二：新增协议（华为云）

```text
【任务】模型托管新增 huaweicloud 协议，走 OpenAI 兼容 /chat/completions。
【约束】同步修改 PROVIDERS、Zod 枚举、前端协议入口；不预设任何厂商域名；不破坏已有 provider。
【验收】node --test test/ai-services.test.js 全绿。
```

结果：`providers.js`、`api-schemas.js`、`AddModelModal.tsx`、`ai-services.test.js` 四处同步改动，14/14 通过。

### 6.4 样例三：质量红线

```text
【任务】把"不许编造页码"做成不可放宽的评测项。
【约束】该用例 minimum=1；live 高分不能抵消模板红线；基线回退超阈值即失败。
【验收】覆盖"单题不达标"与"回归超阈值"两条失败路径。
```

结果：`eval/cases.json` 4 条强制项 + Harness 门禁用例（`harness.eval.test.js` 19 条）覆盖。

## 八、真实性声明与已知局限

1. **不是全自动生成**：架构取舍、安全策略、商业判断、最终验收由人负责；码道承担拆解、生成、重构、排错、测试与文档起草。
2. **会话快照有限**：编辑器只保留最近一次编辑的 `.original` 备份，因此只能证明最近一轮编辑；更早过程以 Git 提交与文档时间戳为证。
3. **未伪造 AI 调用**：配置密钥时经 Sophnet 网关真实调用模型；无密钥时回退演示模板并在界面与文档中明示，不把模板结果当真实模型输出。
4. **未夸大华为云**：完成协议层适配与用例，但未用真实租户密钥做端到端验证，方案文档中已标注"待验证"。
5. **待补录材料**：现场演示录屏（环境搭建、真实生成、故障修复各 30 秒）尚未归档，赛前补齐。
