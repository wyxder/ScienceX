## 三、证据真实性分级

| 等级 | 含义 | 本目录对应材料 |
| :---: | :--- | :--- |
| **A · 原始导出** | 由命令或工具直接产生，未经人工改写 | `evidence/git-log-*.txt`、`evidence/snapshot-index.txt`、`evidence/snapshots/`、`evidence/backend-test.txt`、`evidence/verify-report.txt` |
| **B · 人工整理** | 依据原始证据整理成可读文档，内容与原始证据一一对应 | `01`、`02`、`03` 三份记录 |
| **C · 待补录** | 需要人工在编辑器/浏览器中操作并截取，当前尚未归档 | `screenshots/` 下 8 张截图与 3 段录屏 |

**必须说明的局限**：

1. 编辑器只保留**最近一次编辑**的原文件快照，因此 `evidence/snapshots/` 只能证明 2 个会话（2026-11-22 20:10–20:39、23:12–23:15）的编辑行为；更早过程以 Git 提交历史与文档时间戳为证。
2. 部分快照为 0 字节，对应"新建文件/整体重写"场景，不代表文件缺失；其修改结果可在对应提交的 diff 中核对。
3. 本项目是**人机协作**产物：架构取舍、安全策略、商业判断与最终验收由人负责；码道承担拆解、生成、重构、排错、测试与文档起草。不把"可接入"写成"已验证"，不把演示模板写成真实模型输出。
