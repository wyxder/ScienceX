## 三、Prompt 设计方法：五段式

```text
【角色】在 ScienceX 仓库中工作的全栈工程师，遵循 AGENTS.md 与既有代码风格。
【上下文】相关文件清单 / 现有契约位置 / 不可改动范围。
【任务】要实现的行为、输入输出结构、异常分支。
【约束】不新增依赖；沿用统一响应与错误码；SSE 事件顺序不变；不编造数据。
【验收】给出可执行命令与预期结果；失败先定位根因。
```

| 要素 | 作用 | 缺失后果 |
| :--- | :--- | :--- |
| 角色 | 约束代码风格与规则来源 | 生成风格漂移、无视 AGENTS.md |
| 上下文 | 限定文件范围与契约位置 | 改错文件、破坏既有接口 |
| 任务 | 明确行为与异常分支 | 只做 happy path |
| 约束 | 禁止新增依赖、禁止编造 | 引入不可控依赖、假数据 |
| 验收 | 给出命令与预期 | 无法判断是否真正完成 |

**反面示例**（实际避免）：

```text
"帮我优化一下支付页面。"
```

问题：没有现象、没有范围、没有验收，生成结果无法验证，也无法判断是否引入回归。

## 四、工具使用效率

| 手段 | 具体做法 | 效果 |
| :--- | :--- | :--- |
| 并行读取 | 一次读取 README + 评分文档 + 复盘文档 + 交付物汇总（4 个文件） | 减少往返，先建立全局事实 |
| 批量编辑 | 同模块多文件在同一轮提交（后端枚举 + 契约 + 前端 + 用例） | 避免契约漂移 |
| 最小验证集 | 先跑 `ai-services.test.js`（0.7s），再跑全量 74 条 | 快速失败、快速反馈 |
| 规则固化 | `AGENTS.md` 规定每 2 次修改自动提交、中文语义化 | 过程可追溯，无需手工补记 |
| 证据留存 | 利用编辑器 `.original` 快照 + 命令原始输出 | 证明可核查，不靠自述 |
